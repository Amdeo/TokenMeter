# ADR-0001: 凭据迁移包的加密容器与事务协议

- 状态：已接受
- 日期：2026-09-09
- 相关术语：`CONTEXT.md` 中的「凭据迁移包」「订阅标识」；`CredentialMigrationService`、`MigrationJournal`

## 背景

用户需要把 TokenMeter 的订阅配置与登录凭据迁移到另一台 Mac。订阅存在 `subscriptions.json`（不含机密），凭据存在 `credentials.json`（明文、0600）。导出文件的保护边界与本地文件不同（可能进入云盘、聊天、备份），而核心迁移价值正是凭据本身。

## 决策

### 1. 迁移包为强制密码加密容器

- 外层仅含 `magic`、`schemaVersion`、KDF 参数、`salt`、`nonce`、`ciphertext`；解码时严格校验字段集合与参数范围（未知字段整包拒绝）。
- 密码至少 12 字符、导出输入两次、不保存、不可找回；错误统一报「密码错误或文件已损坏」，不泄露密文结构。
- PBKDF2-HMAC-SHA256 迭代数在导出时实测校准至约 150–300ms（上下限 100k–5M），AES-GCM 认证加密。
- 导出全程内存封装，不产生明文临时文件；保存后验证 0600。

### 2. 错误语义分层：整包拒绝 vs 逐项宽容

- 整包拒绝（落盘前）：magic/类型、版本高于当前、密码错误/AEAD 失败、KDF 越界、顶层解析失败、大小/条数超限。AEAD 失败绝不降级为「无凭据」继续导入。
- 逐项宽容（独立 wire DTO，单条错误不连坐）：重复 UUID 全跳过、UUID 对应不同供应商跳过、未知供应商跳过、凭据结构异常按「无有效凭据」处理。
- 「无有效凭据」永远不是删除指令：本地凭据默认保留；删除必须由用户逐项明确选择。
- 导入前生成不可变计划，摘要展示分类计数与受影响名称，用户可逐项勾选；提交只执行该计划。

### 3. 事务协议：journal + 订阅回滚，绝不备份凭据明文

`credentials.json` 本身是明文，任何凭据备份（含加密备份）都会新增明文泄露面，因此被禁止。一致性由写入顺序保证：

1. 原子写 journal（`staged=true` + 旧订阅 JSON 明文 + 新凭据文件 SHA-256）；
2. 原子写 `subscriptions.json`；
3. 原子写 `credentials.json`；
4. 校验磁盘凭据 hash 与 journal 一致后删 journal。

崩溃恢复（启动时、共享锁内）：journal 存在时校验 `staged`、hash 长度、旧订阅可解码；磁盘凭据 hash 匹配 → 保留新状态仅删 journal；不匹配 → 回滚订阅、删 journal。凭据永远在订阅之后写，因此不会出现「新凭据 + 旧配置」；「凭据写入失败」只会是「订阅新 + 凭据旧」，回滚订阅即可。删 journal 失败不回滚（幂等，下次启动清理）。

### 4. 并发边界：进程级锁 + 迁移门闩

- `CredentialStore` 锁改为进程级共享（static NSRecursiveLock）：Provider 会创建多个实例，实例锁无法保护同一文件。
- `UsageStore` 迁移门闩覆盖「等待/取消旧刷新 → 提交 → 内存更新 → 受控刷新」全程，禁止任何新刷新取得旧配置；提交成功后只放行绑定新配置的一次受控刷新。

## 已知限制

- journal 的 SHA-256 无密钥认证，防不了同一用户的恶意进程篡改——但该威胁模型下 `credentials.json`/`subscriptions.json` 本身同样可被直接改写，未引入新的信任边界。
- 无显式 fsync：目标是应用崩溃恢复，不承诺断电持久化。
- 文件选择器与确认页等 UI 已编译与单测覆盖，未做人工交互测试。

## 备选方案

- **Keychain 一次性密钥 + 加密凭据备份**：凭据备份仍含机密副本且引入 Keychain 生命周期与测试复杂度，否决。
- **明文导出 + 权限警告**：导出文件离开本地权限边界后等同密钥泄露，否决。
- **启动恢复失败静默**：改为暴露 `lastMigrationRecoveryError` 并在设置页展示，避免按半提交状态继续。
